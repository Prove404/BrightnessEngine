# Run FSM2 (Fortran)

Use this skill when the user asks to:
- Run the baseline FSM2 Fortran model for validation or comparison.
- Preprocess or parse meteorological forcing data (CSV, JSON, ERA5) into the strict text format expected by FSM2.
- Post-process Fortran outputs format back into easy-to-use tabular formats.
- Plot FSM2 outputs (SWE, Snow Depth, Albedo, Temperature) and compare them side-by-side to the Unreal Engine C++ port results.

## Scripts & Tools

The original utility scripts have been relocated to `.agents/skills/run-fsm2/scripts/`:

### 1. `RunFortran/` (Data Prepping & Execution)
- `convert_csv_to_fsm2.py`: Pre-processes CSV forcing data into the layout FSM2 expects.
- `convert_json_to_fsm2.py`: Data parser for JSON meteorological forcing.
- `run_fsm2_from_csv.py`, `run_fsm2_all_cells.py`, `run_fsm2_era5.py`: Automation wrappers to execute the Fortran binary `FSM2` for single or multiple cells and pass parameters. Note: Some scripts might use WSL based on the local environment compilation (`run_fsm2_from_csv_wsl.py`).
- `process_fsm2_outputs.py`, `convert_fsm2_to_csv.py`: Scripts to parse the raw generic Fortran text outputs into analysis-friendly readable tabular CSVs.

### 2. `Compare/` (Plotting & Diagnostics)
- `compare_cpp_fortran_fsm2.py`: Master plotting script that generates side-by-side diagnostic plots of the Fortran baseline output against actual Unreal Engine (C++) outputs (SWE, layer temperatures, runtime performance).
- `compare_degreeday_fsm2.py`: Compares physical models (Degree-day vs. FSM2 base).
- `compare_fortran_cpp_melt_season.py`, `compare_fsm2_melt.py`: Focused diagnostics specifically on melt-rate timing and phase shifts.

## Workflow

1. **Check & Prepare Forcing**: Validate the raw forcing data (JSON/CSV) (e.g., ensure no NaNs in Shortwave radiation or Air Temperature). Use the `RunFortran` parsing tools to create valid driver files for FSM2.
   - *Requirement*: Always save the generated/converted forcing data text files into a tidy target folder, such as `analysis_results/FSM2_ForcingData/` or `Saved/Forcing/`, ensuring they do not clutter the root directory.
2. **Parameters Configuration**: Update or verify FSM2 configuration files/parameters (like threshold temperatures, initial states, albedo settings) within the runner script configuration blocks prior to executing.
3. **Execution**: Execute the FSM2 model (if `FSM2.exe` on Windows natively or using WSL). Always log the standard output for errors (like non-converging routines).
   - *Requirement*: Ensure all raw state and flux outputs generated by the Fortran execution are written correctly and cleanly.
4. **Post-Processing & Plotting**: Use the utilities to read checking outputs and then run the appropriate scripts from the `Compare` directory to plot the behavior.
   - *Requirement*: Store plots in `analysis_results/Plots/Comparison/`.

## Best Practices
- **Data Organization & Archiving Runs**: Never clutter the main project path with loose data files.
   - Baseline raw outputs (`fsm2_state.csv`, `fsm2_flux.csv`) should be organized into timestamped/variant directories and placed under `analysis_results/FSM2_FortranOutputs/` (e.g. `analysis_results/FSM2_FortranOutputs/Base_20251014/`).
   - Unreal Engine C++ diagnostics should be similarly managed and read from `analysis_results/FSM2_OutputsUE/` or `Saved/Diagnostics/`.
- **Parameter Synchronization**: Ensure parameter parity between the C++ system (like UE `SnowSimulationActor`) and the Fortran execution script to ensure true apples-to-apples validation comparisons.
